## List clients

```
GET /api/v1/clients
```

Any role. Returns every client in the organization, sorted by name.

`shareToken` (the secret in the client's all-projects
[client link](/concepts/clients-and-projects#client-links), or `null`) is
only included for owner and admin keys. A member's key gets each client
without it, here and when creating a client.

```bash
curl https://<your-instance>/api/v1/clients \
  -H "Authorization: Bearer ch_live_..."
```

```json
{
  "clients": [
    {
      "id": "cm9...",
      "name": "Fintra Labs",
      "email": "hello@fintralabs.com",
      "phone": null,
      "address": null,
      "billingEmail": null,
      "paymentTerms": null,
      "status": "ACTIVE",
      "createdAt": "2026-08-01T14:02:11.000Z",
      "...": "..."
    }
  ]
}
```

## Create a client

```
POST /api/v1/clients
```

Any role. Returns `201` with `{ "client": { ... } }`.

<ParamField body="name" type="string" required>
  Up to 200 characters.
</ParamField>
<ParamField body="email" type="string">
  General contact email. Must be a valid address.
</ParamField>
<ParamField body="phone" type="string">Up to 50 characters.</ParamField>
<ParamField body="address" type="string">Up to 500 characters.</ParamField>
<ParamField body="description" type="string">Up to 2,000 characters.</ParamField>
<ParamField body="status" type="string" default="ACTIVE">
  `ACTIVE` or `INACTIVE`.
</ParamField>

Only these fields are saved; anything else in the body is ignored. Set the
website, billing email and address, and payment terms in the app or with the
MCP `update_client` tool, and payment methods and invoice reminders in the
app.

```bash
curl -X POST https://<your-instance>/api/v1/clients \
  -H "Authorization: Bearer ch_live_..." \
  -H "Content-Type: application/json" \
  -d '{"name": "Fintra Labs", "email": "hello@fintralabs.com"}'
```

**Errors:** `422` with field errors, for example
`{ "error": { "name": ["Name is required"] } }` or
`{ "error": { "email": ["Enter a valid email"] } }`.

## List signed agreements for a client

```
GET /api/v1/clients/{id}/agreements
```

Any role. Returns the client's [signed agreements](/integrations/agreements)
(pulled from DocuSign, Documenso or Ironclad), newest signature first:
client-wide ones, plus those linked to its projects. Agreements on a
confidential project are only included if the key's user can see that
project. Agreements that haven't been linked to a client yet aren't
returned.

<ParamField query="projectId" type="string">
  Only that project's agreements.
</ParamField>

```bash
curl https://<your-instance>/api/v1/clients/cm9.../agreements \
  -H "Authorization: Bearer ch_live_..."
```

```json
{
  "agreements": [
    {
      "id": "cmv...",
      "provider": "DOCUSIGN",
      "title": "Fintra Labs MSA",
      "status": "completed",
      "signedAt": "2026-03-01T17:04:12.697Z",
      "signers": [{ "name": "Dana Ortiz", "email": "dana@fintralabs.com" }],
      "projectId": null,
      "projectName": null,
      "url": "https://app.docusign.com/documents/details/93be49ab-...",
      "hasSignedCopy": true
    }
  ]
}
```

`url` opens the agreement in the provider (the person needs access there).
The signed copy itself is only downloadable in the app.

**Errors:** `404` `{ "error": "Client not found." }` for a client in
another organization or that doesn't exist.
