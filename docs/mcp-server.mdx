---
title: MCP Server
description: Connect an AI coding agent to your Consultainer data
---

Consultainer ships a real [MCP](https://modelcontextprotocol.io) server, so an
AI coding agent can read and write your Consultainer data directly — check
what's unbilled, log hours, or generate an invoice from what actually
shipped, without opening a browser tab.

## Endpoint

```
https://<your-instance>/api/mcp
```

Authenticated with a Bearer token — the same API key used for the
[REST API](/api-reference/introduction). Create one under **Profile → API
keys & AI agents**; that card also shows the exact setup for Claude Code,
Cursor, and Claude Desktop, pre-filled with your instance URL and new key.

## Connecting a client

**Claude Code**

```bash
claude mcp add --transport http consultainer https://<your-instance>/api/mcp \
  --header "Authorization: Bearer <your API key>"
```

**Cursor** (`~/.cursor/mcp.json`)

```json
{
  "mcpServers": {
    "consultainer": {
      "url": "https://<your-instance>/api/mcp",
      "headers": { "Authorization": "Bearer <your API key>" }
    }
  }
}
```

**Claude Desktop** (`claude_desktop_config.json`) — its local config only
speaks stdio, so bridge through [`mcp-remote`](https://www.npmjs.com/package/mcp-remote):

```json
{
  "mcpServers": {
    "consultainer": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://<your-instance>/api/mcp",
               "--header", "Authorization:${CONSULTAINER_AUTH}"],
      "env": { "CONSULTAINER_AUTH": "Bearer <your API key>" }
    }
  }
}
```

If the instance sits behind an authenticating reverse proxy, let `/api/mcp`
(and `/api/v1/*` for the REST API) through without it — the API key is the
authentication.

## Available tools

| Tool | What it does |
| --- | --- |
| `list_clients` | List all clients in the organization. |
| `create_client` | Create a new client. |
| `update_client` | Update an existing client's details. |
| `list_projects` | List projects, optionally filtered by client. |
| `create_project` | Create a new project for a client. |
| `update_project` | Update an existing project's details. |
| `list_my_tasks` | List your open (not-done) tasks, optionally filtered to one project. |
| `create_task` | Create a new task on a project. |
| `update_task` | Update a task's title, description, or hour estimate. |
| `update_task_status` | Update a task's status (TODO / IN_PROGRESS / DONE). |
| `list_task_comments` | List a task's internal comments. |
| `add_task_comment` | Comment on a task (internal; also posted to Linear on linked tasks unless `postToLinear` is false). |
| `watch_task` | Follow or stop following a task's comments. |
| `delete_task_comment` | Delete a comment (your own, or any as owner/admin). |
| `list_audit_log` | Owner/admin: who changed what, with filters. |
| `log_time` | Log time against a project for yourself. |
| `list_meetings` | Your unsorted calendar meetings, with a suggested project for each. |
| `log_meeting` | Log a meeting as time on a project (optionally for its whole series). |
| `ignore_meeting` | Mark a meeting as not project work. |
| `start_timer` | Start a timer on a task or project (stops and logs any running timer first). |
| `stop_timer` | Stop your running timer and log it as a time entry. |
| `get_active_timer` | Your running timer and how long it's been going, if any. |
| `submit_timesheet` | Submit a week of your time for approval. |
| `list_pending_timesheets` | Owner/admin: submitted timesheets waiting for review. |
| `review_timesheet` | Owner/admin: approve a timesheet or send it back with a note. |
| `list_time_entries` | List your logged time entries, optionally filtered. |
| `update_time_entry` | Update one of your time entries (if not yet invoiced). |
| `delete_time_entry` | Delete one of your time entries (if not yet invoiced). |
| `list_milestones` | List fixed-price milestones for a project. |
| `create_milestone` | Create a fixed-price milestone. |
| `update_milestone` | Update a milestone (if not yet invoiced). |
| `complete_milestone` | Mark a milestone complete with a note. Evidence file uploads aren't supported over MCP. |
| `reopen_milestone` | Clear a milestone's completion (if not yet invoiced). |
| `list_expenses` | List expenses, optionally filtered by project or status. |
| `log_expense` | Submit an expense against a project. Receipt file uploads aren't supported over MCP. |
| `approve_expense` | Approve a pending expense. Owner/admin only. |
| `reject_expense` | Reject a pending expense. Owner/admin only. |
| `list_invoices` | List invoices in the organization, optionally by status. Includes isOverdue/daysOverdue per invoice. |
| `generate_invoice` | Generate a draft invoice from unbilled time, milestones, and/or expenses. Owner/admin only. |
| `email_invoice` | Email an invoice to the client with a tracked link to view and pay it. |
| `get_invoice_activity` | When an invoice was emailed, reminded, and opened, plus its client link. |
| `mark_invoice_sent` | Mark a draft invoice as sent. |
| `mark_invoice_paid` | Mark an invoice as paid, optionally with a payment method. |
| `void_invoice` | Void an invoice. |
| `list_members` | List the organization's team members and their roles. |

## Example

```
> What am I working on for Fintra Labs?
Auth flow security review, API migration (2 open tasks)

> Log 3.5 hours on the API migration
✓ Logged 3.50h to Fintra Labs — API migration
```
